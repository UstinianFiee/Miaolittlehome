# 部署手册（极简版）

> 照着做就行。需要更细的排障与核对清单，看 [DEPLOY.md](./DEPLOY.md)。

## 一、前提

- 一台 Linux 服务器，已装 **Docker** 与 **Docker Compose**
- 把本项目传到服务器上（解压 zip 即可）

## 二、部署（三条命令）

在**项目根目录**执行：

```bash
# 1) 建数据目录（容器以 uid 1001 运行，必须先授权，否则启动失败）
#    ⚠️ 以前部署过就别删 /data —— 数据库和媒体文件全在里面
sudo mkdir -p /data && sudo chown -R 1001:1001 /data

# 2) 准备配置
cp deploy/.env.production.example .env.production
# 编辑 .env.production，至少改这 4 项：
#   JWT_SECRET           → 随机长字符串（openssl rand -base64 48）
#   ADMIN_PASSWORD       → 你的后台密码
#   IP_HASH_SALT         → 随机字符串
#   NEXT_PUBLIC_SITE_URL → 对外地址，例如 http://你的IP 或 https://你的域名
# 首次部署再把 RUN_SEED 改成 true（写入示例数据 + 管理员账号）

# 3) 构建并启动
#    --env-file 不能省：构建期要把上面的地址内联进产物
docker compose --env-file .env.production up -d --build
```

打开 `http://服务器IP/` 就能看到站点；后台在 `http://服务器IP/admin`，
用 `.env.production` 里的 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 登录。

> 构建第一次要几分钟（下依赖），之后有缓存会快很多。国内软件源已默认配好。

## 三、常用命令

| 想做什么 | 命令 |
|---|---|
| 看日志 | `docker compose logs -f app` |
| 重启应用 | `docker compose restart app` |
| 更新代码后重新部署 | `docker compose --env-file .env.production up -d --build` |
| 停止 | `docker compose down` |
| 立即备份 | `sudo bash scripts/backup.sh` |
| 查看数据 | `ls /data` |

## 四、首次部署后

1. 登录 `/admin`，在**设置中心**把站点信息、个人资料改成自己的
2. 把 `.env.production` 里的 `RUN_SEED` 改回 `false`，再 `docker compose up -d`（避免每次启动重复写种子）
3. 需要 HTTPS：证书放进 `deploy/nginx/certs/`（`fullchain.pem` + `privkey.pem`），
   再启用 `deploy/nginx/ssl.conf.example`，然后 `docker compose restart nginx`

## 五、数据都在一个目录

宿主机 `/data`：

```
/data/db/blog.db     SQLite 数据库
/data/media          图片、音频
/data/software       安装包
/data/backups        备份包（自动保留 12 份）
```

**备份 = 备份 `/data` 这一个目录**，没有别的。

## 六、遇到问题

| 现象 | 处理 |
|---|---|
| 刚起来时 502 | 容器还在启动，等 30 秒再刷新 |
| 登录后跳不回后台 | 在 `.env.production` 加一行 `SESSION_COOKIE_SECURE=false`，再 `docker compose up -d`（纯 HTTP 访问时用） |
| 页面还是旧内容 | 前台是 60 秒 ISR，等一分钟；或在后台改一次内容触发刷新 |
| 改了 `deploy/nginx/nginx.conf` | 要 `docker compose restart nginx` 才生效 |
| 端口 80 被占用 | 改 `docker-compose.yml` 里 nginx 的端口映射 |
