# 部署手册（极简）

仅适用于**全新空库**。已有站点请用 [更新手册](./更新手册.md)，不要重新初始化。服务器需已安装 Git、Docker 与 Docker Compose v2，并开放网站所需端口。

## 1. 获取项目和准备配置

在 Linux 服务器的 Bash 中执行；任一步失败就停止。默认使用专用宿主机目录 `/data`，已有内容时不能继续本流程。

```bash
set -euo pipefail
git clone https://github.com/UstinianFiee/Miaolittlehome.git blog
cd blog

sudo mkdir -p /data
DATA_CONTENTS="$(sudo ls -A /data)"
test -z "$DATA_CONTENTS"  # 非空则停止，不能清空或覆盖
sudo chown 1001:1001 /data

umask 077
test ! -e .env.production
cp deploy/.env.production.example .env.production
chmod 600 .env.production
openssl rand -base64 48  # 将输出填入 JWT_SECRET
openssl rand -base64 24  # 将输出填入 IP_HASH_SALT
```

编辑 `.env.production`：填写 `JWT_SECRET`、`IP_HASH_SALT`、强密码 `ADMIN_PASSWORD`，确认 `ADMIN_USERNAME`；将 `NEXT_PUBLIC_SITE_URL` 设为实际访问地址（先用 HTTP 就填 HTTP），**仅本次空库初始化**设置 `RUN_SEED=true`。不要公开配置或密钥。

## 2. 启动并关闭初始化开关

```bash
docker compose --env-file .env.production up -d --build
docker compose --env-file .env.production ps
docker compose --env-file .env.production logs --tail=80 app
```

访问服务器地址，后台在 `/admin`，使用配置里的管理员账号登录。确认初始化成功后，**先**将 `.env.production` 中 `RUN_SEED` 改为 `false`，再执行：

```bash
docker compose --env-file .env.production up -d --no-deps app
docker compose --env-file .env.production restart nginx
```

此后再到后台修改个人资料、站点设置和文章。seed 会覆盖已有管理员密码、部分设置和同名示例内容，不能在升级时重跑。HTTPS、可选示例媒体与排障见 [详细部署说明](./DEPLOY.md)。

## 数据安全

- 数据库保存文章、评论、设置等；媒体和软件包也在原宿主机 `DATA_DIR`（默认 `/data`）。容器内路径始终为 `/data`，不要把宿主路径填成容器内路径。
- 保留原项目目录、`.env.production`、Nginx 配置与证书；升级不能用模板覆盖生产配置，也不能改变 `DATA_DIR`。
- 备份须先停 app，完整复制实际数据目录（包含存在的 WAL），另存目录外，并同时备份配置和证书。按 [更新手册](./更新手册.md) 操作；不能把现有 `scripts/backup.sh` 当作可靠在线备份。
- **绝不使用 `down` 的 `-v` 选项，也不删除原数据目录。**
