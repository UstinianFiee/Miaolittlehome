# 首次部署（极简）

更新：2026-10-15。**仅限全新站点、空数据目录**；已有站点用 [更新手册](./更新手册.md)。需要 Linux、Git、Docker Compose v2、OpenSSL、sudo，开放 80 端口；HTTPS 另按 [详细说明](./DEPLOY.md#三启用-https) 配置，不能只开放 443 就启用。

## 1. 下载并准备

在同一个 Bash 会话中执行；报错就停止。默认 `/data` 必须是本项目专用空目录，不要清空已有目录。

```bash
set -euo pipefail
git clone https://github.com/UstinianFiee/Miaolittlehome.git blog
cd blog
sudo mkdir -p /data
DATA_CONTENTS="$(sudo ls -A /data)"
test -z "$DATA_CONTENTS"
sudo chown 1001:1001 /data
umask 077
test ! -e .env.production
cp deploy/.env.production.example .env.production
chmod 600 .env.production
openssl rand -base64 48
openssl rand -base64 24
```

## 2. 填配置并启动

编辑 `.env.production`：第一条随机输出填 `JWT_SECRET`，第二条填 `IP_HASH_SALT`；设置 `ADMIN_USERNAME` 和强密码 `ADMIN_PASSWORD`；`NEXT_PUBLIC_SITE_URL` 填真实访问地址（尚未配 HTTPS 时填 `http://服务器IP`）；**仅本次初始化**设 `RUN_SEED=true`。其他项保持模板默认，不公开密钥。

```bash
docker compose --env-file .env.production up -d --build --wait
docker compose --env-file .env.production logs --tail=80 app
```

访问网站和 `/admin`，用配置中的账号登录。启动或初始化报错就停止，先看日志。

## 3. 关闭初始化，再使用后台

将原 `.env.production` 的 `RUN_SEED` 改为 `false`，执行：

```bash
docker compose --env-file .env.production up -d --no-deps --wait app
docker compose --env-file .env.production restart nginx
```

确认网站、后台正常后再编辑资料、文章和设置。**不能只改文件后 `restart app`，也不能反复执行 seed。**

**数据在哪：**文章、评论、设置在 `/data/db/blog.db`，图片等在 `/data/media/`，软件在 `/data/software/`；完整保留 `/data` 和原生产配置。不要执行 `docker compose down -v` 或删除数据目录。备份、HTTPS、示例媒体和排障见 [详细说明](./DEPLOY.md)。文档已核对仓库配置，未代替你执行生产部署。
