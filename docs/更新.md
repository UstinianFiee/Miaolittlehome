# 更新手册（最简命令版）

适用：用 Git + Docker Compose 部署的站点。**不重新部署、不重新初始化**，原文章、评论、图片、软件和设置全部保留。
压缩包部署的旧站请看 [压缩包更新手册](./压缩包更新手册.md)。

## 1. 冷备份（必做，1 分钟）

```bash
cd /opt/blog
docker compose --env-file .env.production stop app
sudo tar czf /root/blog-before-update-$(date +%F).tar.gz /data .env.production deploy/nginx/certs
docker compose --env-file .env.production start app
```

## 2. 拉代码并重建

```bash
git pull --ff-only
docker compose --env-file .env.production up -d --build --wait app
docker compose --env-file .env.production up -d --no-deps --force-recreate nginx
```

## 3. 验证

```bash
docker compose --env-file .env.production ps
docker compose --env-file .env.production logs --tail=100 app nginx
```

- 数据库迁移由容器启动时的 `prisma migrate deploy` 自动执行（本次更新新增了索引迁移），**不要手动跑 migrate**
- `RUN_SEED` 必须保持 `false`；绝不能为了让内容出现而重新 seed
- 更新后确认：首页、文章详情、后台登录、图片/视频播放、评论提交

## 4. 回滚（更新后异常时）

```bash
docker compose --env-file .env.production stop app
sudo tar xzf /root/blog-before-update-日期.tar.gz -C /     # 覆盖 /data 与原配置
git checkout <更新前的提交>                                 # git log --oneline 查
docker compose --env-file .env.production up -d --build --wait
```

## 底线

- 不删原数据目录、不执行 `docker compose down -v`
- 不用初始化模板覆盖旧 `.env.production`，不改原 `DATA_DIR`
- 失败就停服务、保留现场，按回滚步骤恢复数据 + 代码

排障与更完整的核对清单见 [DEPLOY.md](./DEPLOY.md)。
