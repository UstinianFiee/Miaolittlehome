## 一、UI 风格

主题色板集中在 `src/app/globals.css` 的 CSS 变量里，**改风格优先改变量，不要逐个组件写死颜色**。

| 元素 | 深色 | 浅色 |
|---|---|---|
| 页面底色 | `#090909` | `#edf2f1`（掺一点青绿，承接品牌光晕） |
| 卡片 / 区块 | `#142a2d` + `#31575a` 边框 | `#fbfefd` + `#cee5e2` 边框（`.surface` 边框再掺 15% 品牌色） |
| 标题 / 正文 | `#eef9f8` / `#d4e8e7` | `#123a3d` / `#2c4448` |
| 次要文字 | `#a9c8c7` | `#4f6b70` |
| 顶部导航栏 | `rgb(18 40 43 / 0.97)`（`--nav-bg`，滚动后） | `rgb(251 254 253 / 0.95)`（`--nav-bg`，滚动后） |
| **苍绿品牌色** | `#39C5BB`（`--brand`，同时直接作 `--primary`） | `#39C5BB`（`--brand`，装饰 / 按钮 / 进度条） |
| 正文强调 / 链接 | `#39C5BB`（深色底对比 7:1，可直接用） | `#0B7670`（`--primary`，由品牌色同色相加深，AA 4.8:1） |
| 主按钮 | `#39C5BB` 底 + `#052E2D` 字（`.btn-brand`） | 同（浅底上 `#39C5BB` 配白字只有 2.1:1，所以反过来用深墨绿字） |
| 杏色 / 淡紫点缀 | `#efbd8d` / `#c9b0ed` | `#995126` / `#71529b` |
| 圆角 | `0.375rem`（小圆角） | 同 |
| 根字号 | `html { font-size: 17px }`（全站 rem 等比放大一档） | 同 |
| 正文字体 | 系统中文无衬线栈（`--font-sans`：PingFang / 微软雅黑 / Noto Sans CJK…） | 同 |
| 展示字体 | 站酷快乐体（`@fontsource/zcool-kuaile`，仅 `--font-display`：站点名 / 页标题 / 区块标题） | 同 |
| 代码字体 | JetBrains Mono（`--font-mono`，只用于 code / pre / kbd / samp） | 同 |

> **品牌色只有一个来源**：`:root` / `.dark` 里的 `--brand: #39C5BB`（= `rgb(57 197 187)`，用户确认的主色调）。
> 所有「看得见品牌」的地方一律用 `--brand`：导航选中下划线、`.section-title` 竖条、内页标题短划线、
> 主按钮、加载条、路由进度条、播放器星环、标签 / 书签 / 便利贴底纹、卡片 hover 光晕、选中文字、滚动条。
> **不要把 `--brand` 直接当正文 / 小字颜色**：浅色底上它只有 2.1:1。需要文字时用 `--primary`
> （浅色为同色相加深的 `#0B7670`，深色直接等于品牌色）。改主色时优先改这两个变量，别逐组件写死。
>
> 标题、正文、次要文字、主题色链接与主按钮文字按 **WCAG AA 4.5:1** 检查色板配对；透明图片背景仍需实看。
> 导航栏必须用 `--nav-bg` 而不是 `bg-card/40`——低不透明度会让背景纹理透进导航文字。
> 视觉截图必须等 `.site-preloader` 的 opacity=0 且 visibility=hidden，并且等 `.page-transition[data-phase=idle]`（React 水合完成）再滚动触发入场；只等 `is-loaded` 会拍到加载遮罩淡出中间帧，或拍到下半页未入场的空白。
>
> **字体分两层（2026-10-21 调整）**：
> `--font-sans`（正文 / 导航 / 按钮 / 表单 / 后台）使用**系统中文无衬线栈**，零字体下载；
> `--font-display`（站点名、页标题、`.section-title` 等大字）保留站酷快乐体。
> 之前两者同栈，等于每个中文页面都要下载这套字体的十几个 unicode-range 分片（约 300KB+），
> 1Mbps 服务器上首屏要多等 2~3 秒，而且它只有 400 字重，合成粗体发糊、长文阅读偏花哨。
> 现在只有展示标题会命中少量分片。前台与后台两个布局仍要 import 字体（展示标题要用），漏了会静默退化。
> 正文 `.markdown-body` 用 `1rem`（17px）+ `line-height: 1.9`；行内代码/代码块走 `--font-mono`。
> 不要再给中文正文加 `font-semibold` / `font-medium` 靠合成粗体分层次；需要层次用字号、颜色和间距。

**可复用构件类**：

- `.surface` —— 实色内容面板（列表、侧栏、表单和后台共用）；有背景图时用 `--surface-raised`（98% 不透明）和 `--surface-image-shadow`，避免背景染灰文字区域。
- `.surface-glass` —— 阅读面板用 `--reading-bg`（97% 不透明），**不做大面积 backdrop-filter**；只用于文章正文等少量大块内容。
- `.article-panel`（2026-10-18）—— 文章详情页专用：`--reading-bg` 近实色底板 + 圆角/阴影，不再用 84% + 16px 模糊；
  滚动时不再对整块长文面板反复采样背景，桌面和移动端都明显更稳，视觉上仍是浅色阅读面板。
- **文章详情封面**（2026-10-18）—— 详情页顶部**通栏展示 `post.cover`**（移动 16:9、桌面 21:9，`object-cover`，走 `/img/1280/...`），下接标题 / 摘要 / 元信息。
  标题下方 meta 增加**字数**与**估算阅读时长**（中文按字、英文按词，分别 400 字/分、220 词/分）。
- 2026-10-14 清晰度调整：内容底板承担可读性，背景少雾化；标题、正文、辅助文字分级，不靠整块 opacity 降低对比。正文摘要、关于页简介及长文用 `text-foreground`。页面底色与首页地平线颜色保留。
- `.section-title`（竖条标题）、`.tag-pill`（标签胶囊）
- 归档页标题与整条时间线统一放在 `.surface.archive-panel` 中，避免文字直接叠背景图；年份实色青碧主题色、月份有底胶囊、日期与标题分级，链接含键盘焦点。

**布局**：顶部导航是 **fixed 全宽栏**（参考 haoyu233.com，`h-16 sm:h-[4.25rem]`，内容 `max-w-6xl`），
布局层用 `main` 的 `pt-[5.25rem] sm:pt-[5.75rem]` 补占位；首页封面用等量负 margin 拉满全屏。
首页顶部时导航透明、白字，滚动 24px 后变为 `--nav-bg` 实色底板 + 1px 底边线（固定栏不再做 15px 模糊，见滚动优化）。
**向下滚过 220px 时菜单行整体上滑淡出，中央显示站点名**（悬停/聚焦显示「回到顶部」，点击回页首）；
向上滚动或回到顶部附近时菜单恢复。该收起效果只在 ≥768px 启用，移动端保留汉堡菜单。
桌面导航 1280px 起显示，更窄走抽屉。

## 二、首页与波浪

**首页**：全屏封面（背景支持**视频 / 多图轮播 / 单图 / 渐变底**）+ 站点名 + 打字机副标题 + 向下滚动提示
+ **底部多层波浪过渡**；下滑是「北京时间问候语 + 文章列表 + 右侧栏」两栏布局，**首页每页 5 篇、列表页每页 10 篇**，
分页走**路径段**（`/page/N`、`/posts/page/N`）。

> **分页为什么不用 `?page=N`**：页面一旦读 `searchParams`，Next.js 就无法把它预渲染成静态页，
> 每次访问都会重新 SSR + 查库，响应头退化成 `private, no-store`。旧链接由 `next.config.ts` 的 301 兼容。

**封面背景优先级**：视频 > 多图轮播 > 单图 > 渐变底。轮播 7 秒交叉淡入淡出，图层**按需挂载**并提前预取下一张；
视频静音循环、用第一张图做 poster。

**没有背景图时的兜底封面**（`.hero-fallback`，2026-10-18 重做）：以前是 24% 主色径向的浅色渐变，
浅色主题下几乎和页面同色，白色标题 / 透明导航直接糊掉（截图实测对比度极低）。现在是
「深青底 `#061f22 → #0d4b47` + 两团苍绿极光 + 一层很淡的点阵」：白字对比度足够，
也保证了没配图时首屏仍有品牌质感。极光只动 `transform / opacity`（合成层），
并在 `prefers-reduced-motion` 下停止。真机上请用「站点设置里不配任何首页背景」的状态验收。

**封面入场是有顺序的**（`hero-intro.tsx` + `hero-title.tsx`）：
站点名**逐字显现**（每字 110ms 错开）→ 全部落定后整行泛一次柔光收尾 → `onDone` 回调
→ 副标题的打字机和下滑箭头才淡入出现。副标题在 ready 前用同尺寸占位撑住布局，避免出现时顶跳。
早先是「每字无限上下起伏 + 整行呼吸光晕」两个常驻动画叠在一起，视觉很杂，已收敛成这一次性序列。
所有动画尊重 `prefers-reduced-motion`（直接落定并立即回调）。

**文章卡片保持横向布局**（`post-card.tsx`，文字在左、封面在右，列表仍是单列），
但封面从早先 160×96 的小缩略图**放大到撑满卡片高度**（`self-stretch`，桌面宽 256px），
让封面真正成为视觉主体 —— 参考的是 Elykia 一类博客里「封面大幅清晰」的观感，
**不改排列方式**（曾改成竖卡 + 双列网格，用户明确说不要）。封面走 `/img/640/...`，
并用 `ImageSkeleton` 在图片解码完成前垫一层 shimmer —— 封面是 `loading="lazy"`，
滚到可见才开始下载，没有骨架时那块空白很突兀。没有封面时不预留图位。

**封面视频铺满**（`.hero-video` + `hero-background.tsx`）：部分手机浏览器（安卓 X5 / 旧 WebView）
**不认 `<video>` 上的 `object-fit`**，会按原始比例居中、上下留黑边。组件里用 JS 量出 cover 尺寸写成内联宽高，
外层 `overflow: hidden` 裁剪 —— 盒子宽高比等于视频比例，所以无论浏览器按 `cover` 还是 `contain` 处理都正好填满。
**必须同时写 `max-width: none`**：Tailwind Preflight 给 `img/video` 加了 `max-width: 100%`，
会把量出来的宽度夹回容器宽（实测 1444px 被夹成 375px）。

**封面高度**用自定义类 `.hero-shell`，**不要直接用 Tailwind 的 `min-h-svh`**：svh 要 iOS 15.4 / Chrome 108 起，
老浏览器会丢掉这条声明、整屏封面塌成一条横幅。写法是 `100vh` 兜底 + `@supports (min-height:100svh)` 覆盖。
**不能在同一条规则里写两遍 `min-height` 当兜底**——构建期的 Lightning CSS 会当成重复声明删掉前一条。

**底部多层波浪**（`hero-waves.tsx`，2026-10-18 按 haoyu233.com 的 gentle-wave 改版）：
4 层同一波形 `<use>`，y 依次偏移 0/3/5/7，透明度 `0.7 / 0.5 / 0.3 / 1`，
duration `7 / 10 / 13 / 20s`，负 delay 错开，`translate3d(-90px → 85px)` 无缝漂移。
填充色 = 内容区背景 `--background`，所以和下方内容零接缝；容器高 `80px`（移动）/`100px`（≥640px），
`margin-bottom:-7px` 处理 Safari 底部缝隙。`prefers-reduced-motion` 下停止。
**注意**：即使配置了内容区背景图，首页也**始终使用经典波浪**，不再切换丝带/大曲线方案；
内容区顶部会铺一段 56px 的「背景色 → 透明」过渡带（`.has-page-bg .home-bg-bridge`），
让实色波浪底边平滑过渡到照片，既不出现硬接缝，也不会把封面主体裁掉。

## 三、站点可配置项

设置中心 → 站点信息：名称（页签标题 / 页脚）、副标题、作者、描述、Logo、页签图标、
首页背景图（多张轮播）、首页背景视频、内容区背景图（首页封面下方 + 各内页）、文章页背景图、
ICP 备案号 / 链接、公安网备号 / 链接 / **公安备案图标**。
所有媒体字段都支持**直接上传**或**从媒体库选图**（`MediaField`，属性是 `options` 不是 `images`）。

- 公安备案图标显示在页脚公安网备号前面：后台留空时用内置 `public/police-badge.png`，
  配置后可以是媒体库图片（自动走 `/img/128/` 缩放）；样式是 `.footer-filing__badge`（高 1rem、等比、透明 PNG）。

- 站点名 / 作者 / 描述还驱动 `generateMetadata` 与关于页；
- **页签图标未单独设置时自动回退到 Logo**；
- 内容区背景图用轻模糊与渐变遮罩（`.page-background-scrim`）：`backdrop-filter: blur(2px)`，不再降饱和。
  `--scrim-top/middle/bottom` 控制遮罩：浅色 48% → 30% → 22%，深色 58% → 42% → 34%。
  外层加 `has-page-bg`，文章/侧栏卡片使用 98% 不透明底色；正文阅读面板默认 97%，文章详情使用近实色 `.article-panel`，说说气泡仍为独立不透明青碧色底。
  **不要只减遮罩而保留透明正文**：照片花纹会穿透文字；应同时保证内容底板足够实。
  文章页复用同一遮罩；首页地平线按「与内容区完全一致」填充，不随内容遮罩改色；
- 后台**所有媒体地址字段**统一走 `MediaField`（可手填 / 上传 / 从媒体库挑）：
  站点信息（Logo、页签图标、各背景图、背景视频）、个人资料头像、文章封面、
  说说配图、相册封面、友链头像、软件图标、视频封面与本地视频源、播放器曲目与封面。
- **页签图标不要用 `src/app/favicon.ico` 文件约定**：它会自动生成
  `<link rel="icon" href="/favicon.ico" sizes="16x16">`，而浏览器挑页签图标时**优先精确尺寸匹配**，
  会一直选中它，设置里配的 favicon（无 sizes）永远不显示。内置图标已挪到 **`public/favicon.ico`**
  （`/favicon.ico` 仍可访问，但不再注入 link），由布局的 `generateMetadata` 统一声明 `icons`。

**页脚**（2026-10-18 精简版）：浅灰底（`--footer-bg`，浅 `#f5f5f5` / 深 `#151515`）、
左对齐、小字号，顶部一条极淡的品牌流光。结构压缩到两行：
1. 站点 Logo 胶囊 + 主题切换（浅色 / 深色 / 跟随系统）；
2. 左侧版权 + `Powered by Next.js`，右侧 ICP 备案 / 公网安备；
   ICP 用 `BadgeCheckIcon`，公安网备用图片图标（后台可换，留空回退内置 `public/police-badge.png`），
   中间用细竖线分隔，链接带 `title` / `aria-label`，没配置的不渲染。手机自动堆叠成两行。
不再单独占一行 powered / 技术栈 / 备案，桌面高度约减少一半；手机底部保留播放器避让空间。

## 四、说说（短内容）

说说和文章是**两张表**，但首页要按时间混在一条流里，所以 `listPublishedFeed()` 的做法是：

1. 只取两张表的 `(id, pinned, createdAt)` —— 数据量很小（每条几十字节）；
2. 在 JS 里按「置顶优先 → 时间倒序」合并排序，切出当前页；
3. 再按 id 批量取这一页的完整记录。

**不能**分别对两张表分页再合并 —— 那样分页边界会错（某一页可能只剩一两条）。
Prisma 也不支持 union 后分页，所以走上面这条路。数据量大到几十万条时才需要换成
带游标的统一视图，现在这个量级完全够用。

**气泡卡片**（`shuoshuo-card.tsx`）刻意做得和文章卡片不一样（主题色底 + 尾巴 + 头像），
好让人一眼分清长文和碎念。头像取**「关于」页设置的那个**（没设再回退站点 Logo）；
顶部署名显示**作者名**（`profile.name` → 站点 `author` → 站点名兜底），不是站点名。

尾巴是这里唯一需要动点脑子的地方（2026-10-18 重做）：

- 尾巴现在**不再是气泡内部元素**，而是 `.bubble` 的**兄弟节点**（`.bubble-tail`），
  `position:absolute; z-index:0`，旋转 45° 的方块只露左半边；气泡本体 `z-index:1` 盖住根部。
- 尾巴两条斜边单独描边，底边由气泡自己的边框闭合 —— 轮廓天然连续，
  不会再出现「用 SVG 去补左边框」时亚像素叠加产生的 0.5~1px 接缝（用户截图指出的位置）。
- 尾巴填充必须用不透明的 `--bubble-bg`，否则根部会透出背景；`.bubble` 加 `isolation` 不必要，
  靠层级即可（气泡本身有背景色，会盖住方块右半边）。
- 这比「把尾巴放在气泡前面、再用同色填充盖边框」稳得多，改的时候别退回去。

配图**不要单独加边框** —— 气泡本身已有边框，再套一层就是「框中框」。

气泡用独立 `--bubble-bg/border/foreground/muted/shadow`，浅色清亮青碧白、深色为深青灰；作者在顶部，时间/位置在气泡内底部分隔线上，不直接压背景图。左上小圆角、其余大圆角，头像边框与气泡同色。

文章评论区与 `#article-body` 同处 `max-w-6xl` 容器，评论外层只用 `w-full`，**不要再添加 `max-w-3xl`**，否则正文/评论外边缘不齐。

说说**没有详情页**：内容短，气泡里一次就展示完了。独立页 `/shuoshuo` 同样走路径段分页。

## 五、媒体与图片处理

上传的图片会**自动压缩**（`src/lib/media.ts` 的 `optimizeImage`）：

- 最长边超过 **2560px** 时等比缩小；
- **无透明通道的 PNG 转 WebP**（照片类 PNG 常是十几 MB，收益最大）；
- **扩展名以实际内容为准**：上传文件的后缀常与真实格式不符（例如 `.png` 里其实是 JPEG），
  会自动改名，避免 `/media` 返回错误的 `Content-Type`；
- 内容已合规、只是后缀不对时**只重命名，不重新编码**；
- 体积小于 400KB 且尺寸合规的图片**原样保留**；`gif` / `svg` 不做处理；
- 另外生成 640px 的 WebP 缩略图。

历史上传的图片可用维护脚本批量处理（会同步更新数据库里的所有引用）：

```bash
node scripts/optimize-images.mjs
```

**视频没有服务端缩略图**（镜像里没装 ffmpeg，`media.thumb` 恒为 `null`）。
需要封面时用 `components/video-thumb.tsx`：直接渲染 `<video>` + 媒体片段 `#t=1`
让浏览器 seek 到第 1 秒停住。不占存储、不改上传流程、**对已经传过的视频同样有效**。
文件缺失的兜底**不能只靠 `onError`** —— SSR 出来的 `<video>` 在 hydration 之前就开始加载，
`error` 早发完了，必须在 `useEffect` 里主动查 `el.error`。

**分片上传是无状态的**：服务端不记录上传会话，分片直接落 `<MEDIA_DIR>/.tmp/<uploadId>`。
正常流程在 complete（含失败分支）删掉；客户端中途关页面时靠 `sweepStaleUploads()`
（`prepareUpload` 时按小时节流扫一遍，删超过 24h 的）兜底。**别把 `.tmp` 当成「一定会被清掉」**。

**允许的扩展名**在 `src/lib/media-extensions.ts`（纯数据，所以客户端组件也能 import ——
`media.ts` 引了 `sharp` 和 `node:fs`，客户端引不了）。当前：

- 图片：`jpg jpeg png gif webp avif svg`
- 音频：`mp3 m4a wav ogg oga opus flac aac aif aiff wma ape mka amr mid weba`
- 视频：`mp4 m4v webm mov mkv avi flv wmv mpg mpeg m2ts 3gp ogv rmvb`

音频/视频收得比较宽 —— 浏览器放不了（ape / wma / rmvb）也能当"放在站上供下载的文件"用。
判定**只看扩展名**，不信任客户端的 MIME（浏览器给的 `file.type` 经常是空串）。
对应的 `Content-Type` 映射在 `src/lib/serve-file.ts` 的 `COMMON_MIME_TYPES`。

> **刻意不收 `.ts`**：Nginx 自带的 `mime.types` 把它映射成 `text/vnd.trolltech.linguist`
> （那是 Qt 翻译文件），而生产环境媒体由 Nginx 直出，会带着错误的 Content-Type 发出去，
> MPEG-TS 视频在浏览器里根本放不了。要放这类文件请用 `.m2ts`。

> 上传框的 `accept` 用展开的扩展名而不是 `audio/*` / `video/*`：后者在部分系统上
> 会让 flac / mkv 这类冷门格式在选择器里变灰、选不中。

## 六、内容导出 / 导入

后台「备份」页（`/admin/backup`）用来**迁移服务器**：导出一个 `.zip`，在新服务器上导入。

与运维冷备份分工不同：完整恢复须按 [更新手册](./更新手册.md) 停写后备份数据库、媒体和配置。现有 `scripts/backup.sh` 在线打包且排除 WAL，不能作为可靠的一致性备份；
恢复要停服、只能在同版本之间用；这里是**内容级**的，与数据库文件格式无关，跨版本可用。

**包结构**（`src/lib/backup.ts` + `src/lib/zip.ts`）：

```
backup.json         所有内容表的原始数据（含 id 与时间戳）
README.txt          人看的清单：各表条数 + 导入步骤（见下方说明）
media/...           媒体文件（对应 MEDIA_DIR）
software/...        软件安装包（对应 SOFTWARE_DIR，可选）
```

**为什么要有 `README.txt`**：文章、说说这些内容**全都存在 `backup.json` 里**（一张表一个数组），
不是一个个单独的文件。用户解压后只看到 `backup.json` + `media/`，很自然会以为"文章没导出来"。
这份清单就是消除这个误解的。文件名刻意用 ASCII —— Info-ZIP 的 `unzip 6.00` 不认 UTF-8 标志位，
中文条目名解出来是乱码。

`backup.json` 里带 `format` / `formatVersion` / `exportedAt` / `siteName` / `counts`。
导入时若包的版本比程序新会明确拒绝，避免旧程序读出半套数据。
导入端对不认识的条目名一律跳过（`README.txt` 就是靠这个进来的），
**将来往包里加东西不会让旧版本导入失败**。

**刻意不导出**：`User`（密码哈希跨库迁移没有意义，新服务器 `RUN_SEED=true` 会建好管理员）、
`OperationLog` / `VisitLog`（运行痕迹不是内容）。

**导入 = 完整还原**：清空所有内容表后按包重建。**没做「合并模式」**——
表之间的 id 引用（文章→分类、媒体→相册、回复→父评论）在 id 冲突时要做全量重映射，
复杂度和出错面都大得多，而迁移场景本来就是整机替换。
为防手滑，**导入前会自动把当前数据导出成一份快照存进 `BACKUP_DIR`**。

**执行顺序**（`api/admin/backup/upload/complete/route.ts`）：
存快照 → 还原文件 → 写库（事务）。文件那步失败时数据库还没动过，是最安全的中断点；
数据库是「提交点」，在一个 `$transaction` 里完成，要么全成要么全回滚（超时给到 10 分钟）。

**评论必须拓扑排序**：`Comment.parentId` 是自引用，父节点要先入库。
正常导出时 id 升序天然满足，导入时仍做一次排序，
并把「父节点不在包里」的孤儿回复降级成顶层评论，避免整包导入失败。

### ZIP 是自写的（零依赖）

`src/lib/zip.ts` 实现了够用的最小子集：写 `store` + `deflate`，读两者；**不支持 ZIP64**。
理由：ZIP 的存储格式足够简单（本地头 + 数据 + 中央目录 + EOCD），压缩解压直接用 `node:zlib`，
为这点需求引一个依赖不划算。

几个容易踩的点：

- **store 的条目**在写本地头时还不知道 CRC 与大小 → 置 `FLAG_DATA_DESCRIPTOR`，
  把 CRC / 大小写在数据后面的「数据描述符」里（规范内的标准做法）。
- 文件名统一置 **UTF-8 标志位**，否则中文路径在 Windows 上会乱码。
  （服务端生成的文件名都是 ASCII，这只是兜底。）
- **超过 4GB 或条目数 > 65535 直接报错**，而不是悄悄写出一份坏包。
  导出前先算总大小（`prepareBackup`），超限返回 413 —— 一旦开始写响应体，状态码就定死了。
- 自写的包必须让**外部工具**认。验证时用 Python 的 `zipfile` 做了全量 CRC 校验
  （`.verify/zipcheck.py`）。Info-ZIP 的 `unzip 6.00` 也能通过，
  只是它不认 UTF-8 标志位，中文名会显示成乱码（那是它的问题，不是包的）。

### 导出走原生下载，导入走分片上传

**导出**：服务端 `PassThrough` + `Readable.toWeb` 流式输出，前端用隐藏 `<a>` 触发原生下载 ——
不在 JS 内存里攒整包，浏览器自带进度条。
之所以不用 `fetch` + `Blob`：那会把几百 MB 读进页面内存。

**导入**：复用媒体库那套分片内核（`init → chunk → complete`）。备份包可能几百 MB，
一次性 POST 失败就得从头再来。

`BACKUP_DIR` 存放分片临时目录（`.tmp/`）、暂存 zip（`.stage/`）与自动快照，
生产指向 `/data/backups`（compose 已设）。暂存文件在 complete 的 `finally` 里清掉，
另有 `sweepStaging()` 按小时节流清超过 24h 的残留。

## 七、缓存与刷新

`src/lib/revalidate.ts` 统一负责发布后刷新前台。**最容易踩的坑：缓存标签里带路由组。**

实测 `/zh/about` 的缓存标签是：

```
_N_T_/layout
_N_T_/(site)/layout
_N_T_/(site)/[locale]/layout      ← 布局段叫 (site)/[locale]
_N_T_/(site)/[locale]/about/layout
_N_T_/(site)/[locale]/about/page
_N_T_/zh/about
```

所以 `revalidatePath("/[locale]", "layout")` 生成的是 `_N_T_/[locale]/layout`，**对不上、静默失效、不报任何错**
—— 这就是「后台改了站点设置只有首页生效」的原因。必须带上路由组：`revalidatePath("/(site)/[locale]", "layout")`，
一次覆盖所有前台页面（含分页页、详情页）。`/sitemap.xml` 不在前台布局下，要单独刷。

**客户端还有一层路由缓存**：静态页默认 5 分钟（`experimental.staleTimes`），表现为
「后台改完内容，点导航切过去还是旧的」—— 压根没请求服务端。已压到 30 秒。

**已经打开的标签页靠 `ConfigSync` 主动发现变更**：布局把渲染时的「内容版本号」写进 HTML，
`ConfigSync` 每 10 秒问一次 `/api/site-version`，不一致就 `router.refresh()`。

> 版本号（`getSiteVersion()`）**不能只算 `site.*` 设置**。早期只统计站点设置，
> 结果「改了文章 / 视频 / 相册，已经开着的标签页不刷新」—— 因为版本号压根没变。
> 现在它把所有**面向公众**的内容表（文章、分类、标签、说说、公告、相册、媒体、
> 视频、软件、友链、已审核评论、`profile.*` / `playlist`）按 id 排序后一起哈希。
> 刻意**不读** User、日志、`downloads` / `views` 计数与 `ipHash`：那些不影响前台渲染，
> 放进来只会让版本号因为无关写入而抖动（每次浏览量 +1 都会触发全站刷新）。
> 版本号变了但服务端 ISR 还没刷完或刷新失败时，同一目标版本每 30 秒最多重试一次；新目标版本立即刷新，页面版本追平后清除重试记录。不要永久锁住旧页面版本，否则一次失败后就永远不再更新。

**`revalidatePath` 刷新动态段布局必须用路由模式**，传具体路径 + `"layout"` 无效；
**多段动态路由模式**（如 `/[locale]/posts/[slug]`）也无效，要查出真实 slug 逐条刷。

- 轨道与连线是 SVG 虚线（`vector-effect: non-scaling-stroke`，缩放后线宽不变），颜色走主题色。
- **移动端（<768px）整个星系隐藏，换成纵向列表** —— 轨道在小屏上挤成一团，没有可读性。
- 动效全部进 `prefers-reduced-motion` 关闭列表。

### 关于页：错落卡片与可配置资料

`/about` 参考用户提供的关于页模块结构，沿用本站统一主题色，不复制对方身份或兴趣。首屏个人名片，下方为真实公开内容统计、技术清单、社交联系、作品/近期文章、兴趣/站内入口、相册照片、播放列表、长介绍与最新说说。

- 后台设置 → 个人资料新增身份、城市、座右铭、技能、兴趣、作品集、长介绍；存于 `profile.about` JSON，无 schema 迁移，旧请求不传 about 时保留原值，损坏 JSON 回退空资料。
- 技能/兴趣按逗号或换行拆分；作品每行 `名称 | https://地址 | 简介`，只渲染安全协议地址。空技能展示「本站实际技术栈」，不是声称站长掌握；空作品展示已发布文章。其余个人字段为空隐藏。

- 大小错落的 12 列网格，手机单列；图片轻微相纸倾斜、悬浮归正，减少动效时关闭。音乐卡仅展示已有播放列表，引导用全局播放器，不创建第二个播放器。

### 双时间显示（`DualTime`）

docs/SPEC.md 要求同时展示 UTC+8 与 UTC，早期实现是拼一整行
`2026-10-09 14:30 (UTC+8) / 06:30 (UTC)` —— 又长又平，塞进评论、便利贴、后台表格里很杂乱。

现在统一用 `components/site/dual-time.tsx`：**默认只显示读者本地时间**，浏览器通过 `Intl.DateTimeFormat` 自动使用设备时区（按目标日期处理夏令时）。悬浮、键盘聚焦或点击时才展开 UTC 与 UTC+8 的完整日期/时间；点击可固定浮层，再点、点击外部或 Escape 关闭。

- 组件为客户端组件；用 `useSyncExternalStore` 区分水合阶段，SSR 与首次水合统一 UTC+8，随后切本地时间，不关闭 SSR、不牺牲 ISR；无 JS 时保留 UTC+8 主时间。
- 复用已有 Radix Popover Portal 自动避让视口，避免表格/翻牌的 overflow 与 transform 裁切；浮层可悬停，进出有淡入缩放，减少动态效果偏好下关闭动效。
- 时间触发器为原生按钮；公告折叠按钮、视频整卡链接不能包住它，时间点击不翻留言牌、不跳视频页。`variant` 保留调用兼容，默认不再显示 UTC 胶囊。
- `formatDual()` 只保留给纯文本场景（备份包 README、日志详情字符串），界面里不要再用。
- 主题按钮用太阳/月亮旋转缩放与点击光圈；语言按钮悬停提示目标语言，点击翻转并进入忙碌态，180ms 后整页切换（减少动效时立即切换）。主题 Provider 不启用 `disableTransitionOnChange`，否则会取消按钮的 CSS 动画。

### 留言墙不重复渲染评论列表

便利贴本身就是留言的列表，下面再来一遍评论列表是重复的 —— 所以留言墙给
`CommentSection` 传 `formOnly`：**只保留「写留言」表单**（标题也换成「写留言」），
但 `initialComments` 仍要传，它用来判断本地待审项是否已通过审核。

### 评论审核：通过回复必须连带通过上级

`buildTree()`（`src/lib/comments.ts`）在组装评论树时会**丢掉「父留言不可见」的回复** ——
这是「先审后显」的应有行为，但后台一开始只改了回复自己的 `approved`，
于是出现最坑的一种状态：**后台显示「已通过」，前台永远看不到**。

现在 `setCommentApproved()` 在**通过回复时会沿 `parentId` 向上把整条上级链一起通过**
（最多 5 层，与 `buildTree` 的保护上限一致），并把被连带通过的 id 放进返回值 `cascaded`：

- 后台拿到 `cascaded` 后提示「已连带通过 N 条上级留言」，避免"我只点了一条怎么别处也变了"；
- 列表里对「父留言未通过」的回复打红标（`parentApproved` 字段由后台查询顺带取出）；
- **退回顶层留言会连带隐藏它的回复**，所以有回复时先弹确认；
- 删除有回复的留言同理，用更明确的确认文案（级联删除不可恢复）。

> 同类坑：任何"只改叶子、不改祖先"的可见性判断，都要顺着这条线想一遍。

友链名片的顶带**刻意不按 id 派生随机色相** —— 几张名片凑在一起是彩虹色，整页会显得"拼贴"。
改成同一主题色里的深浅变化（`--friend-mix` 在 45%/62%/78% 之间取）。

### 便利贴的四个坑（2026-10-27 修版）

- **底色必须不透明**（与说说气泡同理）：便利贴是 `color-mix(primary, card)` 混出来的，
  而 `--card` 自带 alpha，直接用会在翻牌时**透出背面**。
- **`backface-visibility` 要放在被旋转的那一层**：真正 rotateY 的是外层 `.flip-back`，
  把属性写在内层 `.sticky-note` 上不继承、等于没写，翻牌时会看到两面叠在一起。
- **不要用 CSS columns 做瀑布流**：`columns` 会把绝对定位的子元素（胶带）在多列里重复投影，
  实测第二/三张纸条的胶带会跑到隔壁纸条下面（看起来像"贴错位置"）。现在改成响应式 grid
  （`grid-cols-1 sm:grid-cols-2 lg:grid-cols-3` + `items-start`）。
- **翻面不能靠「背面 absolute + 正面固定 min-h」**：背面内容（头像 + 3 行信息 + 按钮）比正面高时，
  `overflow-hidden` 会把「详情」按钮切掉。现在 `.flip-inner` 用 `display:grid`，正/背面
  `grid-area: 1/1` 叠在同一格，高度取较高的一面，两面都不裁切。
  另外给 `.flip-card:hover / :focus-visible / .flipped` 加 `z-index`，3D 翻转时不会被后面的纸条盖住。

### 留言墙分页：pagination 必须用插槽

`SitePagination` 是 **async 服务端组件**（内部 `await getTranslations()`），
不能直接在客户端组件里 `import` 后用 —— 会抛
`getTranslations is not supported in Client Components`，而且是运行时 500，构建不报错。

所以 `WallView`（客户端）收一个 `pagination?: ReactNode` 插槽，由服务端页面渲染好了传进来。

排序上刻意「顶层按时间倒序分页，回复按时间升序」：最新的一直在最前面，
而每条下面的回复保持"先说的话在前面"。每页 6 条（`WALL_PAGE_SIZE`）；便利贴正面最多显示 120 个 Unicode 码点，超出时单独显示可点击的省略号，点击复用详情弹窗查看全文与回复。

### 分类 vs 标签：刻意做成两种形态

两者原来都是书签，看着像同一个页面换了字。现在：

| 页面 | 形态 | 关键类 |
|---|---|---|
| 分类 | 竖长条书签，挂在横杆上，底部 V 形缺口 | `.bookmark` |
| 标签 | 一墙**小方贴纸**，带固定轻微倾角 + 中缝分割线 | `.tag-card` |

两者的颜色**都走主题色深浅变化**（`color-mix` + 不同占比），不引入随机色相 ——
一墙彩虹色会显得"拼贴"。

### 归档页：时间线

按**年**分包，年份用站点展示字体放大到 4xl/5xl（`text-primary/85`）+ 渐隐横线；
月份降级成小胶囊；每行「日期 | 标题」两列，日期等宽数字对齐；
悬停时节点放大转主题色、标题右移并浮出箭头。

### 导航选中态：不要用灰底

`--accent` 在浅色是 10% 的蓝、深色是 45% 的灰，当选中态的底色会让文字发糊、对比度掉得厉害。
现在改成 **`text-primary` + 底部一条小短横线**（`.nav-item::after`，`scaleX` 动画）：

- 悬停：文字变亮 + 短横线露出半截（`scaleX(0.5)` + 半透明）
- 选中：文字转主题色 + 短横线整条展开（`scaleX(1)`）

`data-active` 属性由 `nav-links.tsx` 打上，CSS 靠属性选择器命中，不用在 JS 里拼类名。
移动端抽屉的「登录」入口也一并去掉了 `hover:bg-accent`。

### 进场加载动画（`SitePreloader`）

**标记写在服务端渲染的 HTML 里，不依赖 JS 执行。** 这是刻意的：前台是 ISR 静态页，
而慢网络下 JS 恰恰是最后到的 —— 纯客户端方案会让加载动画永远赶不上真正需要它的那段空白。

**视觉（2026-10-18 品牌化改版）**：深色品牌开屏，以 **站点 Logo / 个人头像** 为主角：
中央是品牌渐变徽章，Logo/头像在徽章里做**呼吸 + 上下浮动**；外圈两层反向旋转的细轨道、
两颗沿轨道运行的光点、背后缓慢旋转的品牌极光和一道很淡的扫光；下方站名 + 短流光进度条。
Logo 优先取 `site.logo`，没配时由布局读取 `profile.avatar`；两者都没有时回退到站点首字。
纯 CSS，不新增客户端 JS。

- 遮罩默认可见（CSS 默认态就是挂着），内联脚本给 `<html>` 加 `is-loaded`，CSS 据此淡出（并轻微放大）；
- **触发时机不是 `load` 等全部资源**：`load` 可能被背景图拖到十几秒。现在加载完成就准备淡出，
  但保留 **最短 520ms** 的品牌开屏，避免本地快速加载时动画一闪而过；硬上限 **1.2 秒**；
- **每次整页加载都会播放**（刷新、直接打开、语言切换这类整页导航都会走）。曾用 `sessionStorage`
  做过「同一标签页只播一次」，结果同一标签页刷新后动画再也不出现，被当成 bug，已回退；
- `.site-preloader` 设了 **`pointer-events: none`**：它只是视觉过渡，不该在那几百毫秒里把点击全吞掉；
- 它挂在站点布局里，**客户端路由切换不会重新挂载**，所以不会反复播 —— 那种情况交给顶部进度条。

### 客户端异常兜底（`global-error.tsx` / `[locale]/error.tsx`）

线上出现过 Next 内置的英文 `Application error: a client-side exception has occurred`。两个文件分别负责两段：

- **`src/app/(site)/[locale]/error.tsx`**：兜住「页面」部分。它在语言布局**内部**，
  所以只覆盖 `children` 抛出的异常。
- **`src/app/global-error.tsx`**：兜住挂在布局里的组件（`ConfigSync`、顶部导航、悬浮播放器）。
  它在根布局**之外**渲染，必须自带 `<html>`/`<body>`，**不能依赖 next-intl 或项目 CSS 变量**，
  因此文案与样式全部内联、按 `<html lang>` 自行选中英文。

两者都会：把错误打到 console；**判断是否属于"代码分片没取到"**（`ChunkLoadError`、
`Loading chunk N failed`、`Failed to fetch dynamically imported module`…），是的话
**自动 `location.reload()` 一次**，用 `sessionStorage` 里的时间戳做 15 秒节流，避免刷新死循环。

> 为什么必须处理这一条：部署新版本后 `/_next/static/` 的文件名（内容哈希）全变，
> 已经打开的标签页还拿着旧文件名 → 404 → 客户端抛异常。这不是代码坏了，刷新即恢复。
> 实测（`.verify/check-error-boundary.mjs`）：拦截某个页面 chunk 返回 404 时，
> 失败一次会自动刷新并正常渲染；持续失败则显示站点自己的中文兜底页 + 重试/刷新按钮，
> 不再出现英文 `Application error`。

注意：**首屏 HTML 阶段的分片 404 兜不住** —— React 还没启动，任何 React 错误边界都不存在。
那种情况只能靠用户刷新，Next 自身的引导脚本会给出提示。

### 页面标题区的可读性（`.page-heading`）

内容区背景图打开后，各页的标题、副标题和计数是**直接压在照片上**的，照片一亮整片就看不清
（尤其是 `text-muted-foreground` 的辅助文字）。现在这些标题区统一挂 `.page-heading`：

- **只在有背景图时加底**（`site.pageBackground` 存在时布局会挂 `.has-page-bg`）：
  `90% 卡片色 + blur(10px) + 细边框 + 面板同款投影`。没有背景图的站点完全不受影响，
  仍是原来的通透排版（`.page-heading` 只有 `min-width: 0` 和圆角）。
- 用 90% + 模糊而不是纯实色：模糊会把照片的明暗极值抹平，即使背景很暗也能保住对比度，
  同时边缘还透出一点背景，不会变成一块实心卡片。材质沿用站内面板，不引入新视觉语言。
- **已经落在 `.surface` 面板里的标题不要再挂**（否则是双层底）：归档页、文章详情页属于这种。
- 首页的问候语和「最新文章 / N 条」是**合成一个** `.page-heading` 的 ——
  拆成两块会变成两个叠着的横条，看着像拼贴。
- `#home-content` 需要 `scroll-mt-*`（等于 main 的顶部占位）：封面的下滑箭头跳的就是它，
  少了这个偏移滚过去标题会被固定导航栏盖住。

### 懒加载

- 图片统一 `loading="lazy"` + `decoding="async"`（相册大图除外，用 `eager`）。
- 视频缩略图（`video-thumb.tsx`）改成 **IntersectionObserver 进视口才挂 `<video>`** ——
  之前 SSR 就渲染，等于一进页面就全部开始请求。
  注意：**文件缺失的兜底不能只靠 `onError`** —— SSR 的 video 在 hydration 前就开始加载、
  error 早发完了，必须在 `useEffect` 里主动查 `el.error`。

### 文章目录

文章详情从 `renderMarkdown()` 产出的 HTML 提取 h2–h4 标题和 `rehype-slug` 实际生成的 id（`extractMarkdownHeadings()`），
目录直接链接这些 id，避免再实现一份容易与 rehype 规则/重复标题处理不同步的 slug 算法。目录只在桌面右侧栏显示，窄屏隐藏；没有二级以上标题时不显示目录，也不预留空列。侧栏必须 `self-stretch` 给内部 sticky 留出滚动空间，超长目录在视口高度内独立滚动。正文标题已有 `scroll-mt-24`，会避开悬浮导航。文章分享仅保留复制链接和二维码，已按用户要求移除系统分享。

### 后台 Markdown 编辑器为何慢、如何减等待

编辑器慢主要是串行加载链：文章表单先通过 `next/dynamic` 加载 `MarkdownEditor`，组件 mount 后才 `import("vditor")`，
接着 Vditor 再请求自托管的 `/vditor` 静态资源。现在文章编辑器只在文章表单路由引入，移除表单层的额外动态组件加载，
在浏览器评估该路由 chunk 时立即启动 Vditor 核心包下载，并复用同一个 Promise；仍保留 Vditor 核心包的异步分包，
不会让 Vditor 进入公共站点 bundle。`after` 回调到达前显示加载状态；加载异常有明确错误提示。
资源继续由 `scripts/sync-vditor.mjs` 自托管，勿改为第三方 CDN。

### 后台切页与媒体库筛选性能（2026-10-18）

后台最初「点音频/视频筛选就卡住」不是数据库慢，而是三个前端问题叠在一起：

1. **筛选走整页 RSC**：媒体库筛选按钮用 `router.push(?type=...)`，每次切换都重新请求服务端、
   重挂载所有卡片。现在一次读取最多 500 条媒体元数据，类型 / 相册 / 关键词**全部在客户端筛选**，
   用 `history.replaceState` 同步查询串，切换不再发 RSC。
2. **一次渲染几百张卡片**：每张卡都有 Radix Select 和视频缩略图。现在改成 **24 条/页**，
   只渲染当前页；筛选/搜索变化回到第 1 页，底部有上一页/下一页。
3. **改一次名就整页刷新**：删除、改名、改相册现在直接更新本地 `list`，不再 `router.refresh()`；
   只有上传和补视频封面后重新拉一次元数据。

另外：

- 后台侧边栏链接统一 `prefetch={false}`。以前 Next 会把侧边栏里十几个动态页面全部预取，
  每个页面都查库；媒体库打开时还会预取设置/播放器等页的 RSC，白白占带宽和服务端连接。
- `getSiteInfo()` 用 React `cache` 按请求去重：后台/前台布局、`generateMetadata`、页面常各调一次，
  之前同一请求会重复查 Setting 表；现在只查一次（跨请求不缓存，后台保存后立即生效）。
- 后台增加了 `(shell)/loading.tsx` 骨架屏，切页时先给反馈，不再停在旧页面上看起来「没反应」。
- 设置页加了「站点信息 / 个人资料」锚点导航；两个长表单的保存按钮在滚动时吸顶。
- `MediaField` 的媒体选择面板增加关键词搜索；曲目封面预览支持 `compact`，播放列表行高更紧凑。

### 手机端适配（2026-10-18）

这一轮按「内容优先、操作可达」修整，不是简单把桌面布局等比缩小：

- **前台**：`390/360/768` 三档巡检无横向溢出；文章元信息在手机上隐藏「·」分隔符，按信息类型自然换行；
  相册只有一张图时占满整行（`[&>li:only-child]:col-span-full`），避免半格空着。
- **悬浮音乐播放器**：手机端从 `104px` 收到 `64px`，`bottom/right` 走 `safe-area`；
  正文表单（input/textarea/select）聚焦时自动淡出，避免挡住输入框；页面最底部给页脚留出
  `pb-24` 的播放器避让空间，版权和备案不会被盖住。
- **后台顶栏**：≤640px 隐藏「后台管理」徽标、退出登录只留图标，把空间让给站点名；
  ≥640px 恢复完整徽标和文字。
- **后台表格分两类处理**：
  - 内容型（文章、评论、公告、说说）在 `<lg` 改成**移动卡片**，正文和操作都完整可见；
  - 配置/日志型（分类、相册、软件、友链、视频、日志）在 `<lg` 保留表格语义，但 `width:max-content`
    + 横向滑动 + 右侧渐隐 +「左右滑动查看」提示，保证操作列能滑到，不再被压成省略号。
  - `Table` 组件用 `ResizeObserver` 判断是否真的溢出，不溢出时不显示提示。
- **iOS 表单**：`@supports (-webkit-touch-callout: none)` 下把输入框字号提到 16px，避免聚焦自动放大。
- **后台长表单**：设置页保存按钮吸顶；媒体/相册/软件等上传按钮在窄屏自动换行，不挤出卡片。
- 验证：`mobile-overflow.mjs` 扫 36 个页面（前台 + 后台）在 390/360 宽度下
  `documentElement.scrollWidth === innerWidth`；菜单抽屉、播放器聚焦隐藏、页脚避让均做了交互冒烟。

### 文章页滚动性能（2026-10-18）

文章页曾出现「点进去滑动卡卡的」，根因不是文章内容，而是**大面积 backdrop-filter**：
阅读面板占满视口高度、顶部导航固定，滚动时每帧都要重新采样背后的封面/背景图。

- `.article-panel` / `.surface-glass` 改为 `--reading-bg` 近实色底板，**全局去掉大面积模糊**；视觉差异很小，滚动大幅变稳；
- 顶部导航的实心状态、文章导航条同样去掉 `backdrop-filter`，用 `--nav-bg` 实色底板；
- `ArticleBar` 的进度 state 改为 **rAF 帧级节流 + 0.4% 变化阈值**，不会每个 scroll 事件都触发 React 重渲染；
- `HeaderShell` 的滚动态 / 收起态同样用 rAF 合帧，并只在布尔值真正变化时 setState；
- 窄屏继续保留「实色导航 + 吸顶」，视觉层级不靠模糊。

实测（390/950/1440 宽，4× CPU 降速，程序化双向滚动 3 秒）：
950px 下平均帧间隔 **32.6ms → 16.5ms**，>33ms 的慢帧 **84 → 0**；
1440px 下 **33.4ms → 16.9ms**，慢帧 **85 → 4**；390px 下慢帧 **11 → 0**。

## 十、技术约定（踩过坑的）

- **`(site)/[locale]/` 下不要再放 `loading.tsx`**：它会给整棵子树套一层 Suspense，
  Next 会先把外壳流式发出去（状态码 200 已定），之后 `notFound()` 就改不了状态码 → 全站变成软 404。
  想在某个页面加骨架屏，只能加在**不会 404** 的路由段上。
- **「内容不存在」一律走 `notFound()`**，不要 `return` 一段提示文案：后者状态码仍是 200，
  搜索引擎会把 `/posts/随便打的字` 当有效页收录。各动态段的文案放在该段的 `not-found.tsx` 里，
  共用 `components/site/entity-not-found.tsx`。
- **`radix-ui` 必须留在 `experimental.optimizePackageImports` 里**：它是统一包，
  `import { Slot } from "radix-ui"` 会把全部 Radix 原语打进产物（实测每页多背 4 个 chunk、约 268KB）。
- **会话 Cookie 的 `Secure` 按实际请求协议判断**（`src/lib/session.ts` 读 `x-forwarded-proto`），
  不能写死 `NODE_ENV === "production"` —— 用 `http://IP` 访问时浏览器会丢弃 Cookie。
- ⚠️ **`<audio>` 的 `preload` 必须是 `"none"`，不能是 `"metadata"`**（`use-music-audio.ts`）。
  Chrome 对 `preload="metadata"` 会发 `Range: bytes=0-`，而 nginx 的 `/media/` 是
  `alias` + `Accept-Ranges`，会**老老实实把整个文件发回来**。歌单里一旦有无损（FLAC 30MB+），
  首屏就会平白拉走几十 MB —— 实测线上首页 `load` 事件被拖到 **22.4 秒**，音频占全部流量的 94%。
  改成 `"none"` 后浏览器只取到文件头就断开（**300 字节**），`load` 降到 **0.5 秒**；
  真要点播时在 `play()` 里改回 `"auto"`。
  > 顺带建议：无损音频在网页上不划算，**歌单尽量用 MP3/AAC/Opus**。
  > 即使点了播放，2Mbps 的机器上 30MB 也要缓冲很久。
- ⚠️ **不要把相对路径拼到 `request.url` 上做跳转**（`api/software/download/[id]` 踩过）。
  容器里 `request.url` 的主机来自 `HOSTNAME`/`PORT`（compose 里是 `0.0.0.0:3000`），
  不是浏览器访问的域名；`NextResponse.redirect(new URL(path, request.url))` 会 302 到
  `https://0.0.0.0:3000/...`，浏览器直接 `ERR_ADDRESS_INVALID`。
  正确做法是回**相对路径**的 `Location` 头，让浏览器自己解析。
- **封面视频要显式抬高文字层级**：安卓 WebView / 部分国产浏览器会把 `<video>` 提升成
  独立的硬件叠加层（SurfaceView），**那一层不受 z-index 约束**，会盖住同容器里的标题和遮罩
  （表现：电脑正常，手机上只看到视频、文字全没了）。所以 `.hero-video` 带
  `translateZ(0)` + `will-change: transform` 强制走普通合成层，
  `.hero-title` / `.hero-subtitle` 显式 `z-index: 1`。
- ⚠️ **首页底部过渡不要再切回「大曲线 mask + 丝带」方案**（2026-10-18 最终决定）。
  曾经的 `HeroHorizonSilk` 回退会在有内容区背景图时生成一条很高的曲线填充，
  视觉上像一大块白浪把封面人物/云层裁掉；用户实测「只设首页图时正常，一设内容区背景图就坏」。
  现在的结构统一为：
  - 首页始终渲染 `hero-waves.tsx` 的 4 层 gentle-wave，填充内容区背景色；
  - 有内容区背景图时，只在 `#home-content` 顶部加 **56px 全宽**的
    `背景色 → 透明` 渐变带，开始处与波浪的实色底边完全同色，往下再淡出到照片；
  - 渐变带必须 `left:50%; width:100vw; transform:translateX(-50%)`，否则只会盖住
    `max-w-6xl` 内容容器，两侧露出两条照片方块；
  - 不再使用 fixed 背景填充曲线/mask，避免曲线遮住封面主体和取样不一致的割裂线。
  历史坑仍保留供参考：`mask-position` 动画无法走合成层；把 mask 放进
  `will-change: transform` 的合成层会只光栅化一次；100~160px 高的容器内 cover
  与内容区整屏 fixed cover 取样不同，衔接必有亮度差。
- ⚠️ **友链轨道的暂停条件不能用 `:focus-within`**：鼠标点一下友链（尤其「在新标签页打开」）
  之后焦点会留在那个 `<a>` 上，`:focus-within` 一直匹配，动画**永久停住** ——
  用户看到的就是「有时候转有时候不转」「完全不转了」。改用 `:has(:focus-visible)`
  （只有键盘导航聚焦时才暂停）。**全站只有这一处 `focus-within` 配 `animation-play-state`**。
- **媒体库管理端不再为「没有封面」的视频自动抽帧**：旧逻辑会在每张视频卡里挂
  `<video>` 现抽首帧，浏览器发 `Range: bytes=0-` 读取视频；媒体一多就把带宽占满，
  筛选按钮排队，看起来像整页卡死。现在无封面视频只显示「暂无封面」占位，
  需要时点卡片下方的「生成封面」再抽（上传流程本身已生成 `thumb`，只有老视频会没有）。
  这也顺手消掉了 demo 里视频文件缺失时的 404。
- ⚠️ **`VideoThumb`（视频缩略图）仍用于「从媒体库选视频」弹窗，必须限制并发**。
  浏览器取封面帧的方式是发 `Range: bytes=0-`，`preload="metadata"` 时每个缩略图约读 200KB。
  现在：`preload="none"`（每个降到约 64KB）+ **模块级闸门，同一时刻最多 2 个去取帧**。
  **改这个组件时不要去掉 `preload="none"`，也不要放开并发。**
- **Nginx 里 `proxy_set_header Connection "upgrade"` 不要写死在 `location /`**：那会让**每个**
  请求都带 `Connection: upgrade`，`upstream` 的 `keepalive` 直接失效（每个静态资源新建一条到应用容器的连接）。
  正确写法是 `map $http_upgrade $connection_upgrade { default upgrade; '' ""; }` 再用 `$connection_upgrade`，
  并且**放在 server 级** —— `proxy_set_header` 是「location 自己没写才继承 server 级」，
  只写在 `location /` 里的话 `/_next/static/`（请求量最大的那一批）拿不到它。
- **Nginx 的 `add_header` 也是「本层有就不继承上层」**：给 `/_next/static/` 之类加了
  `Cache-Control` 之后，server 级的 `X-Content-Type-Options` 等安全头就丢了。
  用户上传内容那两个 location（`/media/`、`/software-files/`）单独补了 `nosniff`。
- **域名在 `nginx.conf` 里只写一处**（`map $host $site_canonical`）。早先写在 80 段和 443 段的
  `server_name` 里，只改一处会出现「HTTPS 能开、HTTP 直接连不上」：HTTP 的 Host 匹配不上域名 server，
  落到 `default_server` 被 `444` 断掉。
- **80 端口"拒绝其它域名"要写在 `location /` 里，不能写成 server 级 `return`**：
  server 级 `return` 跑在 rewrite 阶段、早于 location 匹配，会把 `/.well-known/acme-challenge/`
  一起挡掉，证书就无法自动续期。（443 段没有 ACME，用 server 级 `if ... return 444` 是安全的。）
- **跳转一定要带 `$request_uri`**：`return 301 https://域名;` 会把所有 HTTP 访问甩到首页，
  深层链接和查询串全丢。
- **HTTPS 上线后必须改 `NEXT_PUBLIC_SITE_URL` 并重新 `--build`**：它是构建期内联的，
  不改的话页面 `hreflang` / `sitemap.xml` / `robots.txt` 里还是旧地址（曾经是容器内的 `http://blog_app`，
  搜索引擎会拿到打不开的链接）。
- **ip2region 离线库约 11MB 且是 `readFileSync`**：靠 `src/instrumentation.ts` 启动预热，
  不要在请求路径上首次加载。同理，middleware 里的访问日志写入不要 `await`。
- **后台登录有失败限频**（`src/lib/login-guard.ts`）：按 IP 记失败次数，15 分钟内满 10 次锁定。
  内存态 —— 单容器部署够用，**横向扩容要换共享存储**。
- **`media.title` 就是上传时的原始文件名**；`PATCH /api/admin/media/[id]` 支持改 `title`，
  媒体库支持点击标题就地重命名。
- **手机端兼容**：手写 CSS 里的 `backdrop-filter` 必须同时写 `-webkit-backdrop-filter`（iOS 18 之前只认前缀）；
  长文本（时间、URL、UA）放在 flex 行里**不要用 `shrink-0`**，窄容器下会顶出视口造成整页左右滑动。
- **`revalidatePath` / ISR 验证前先清 `.next/cache` 或预热**：构建期用的是空/旧配置，
  第一次请求会拿到过期 HTML（stale-while-revalidate），很容易误判成 bug。
- **改路由后必须先删 `.next`** 再跑 `tsc`，否则类型缓存会导致误报。
- **构建后要 `grep MISSING_MESSAGE`**：缺失文案不会让构建失败，只会静默降级。
- **语言切换走整页跳转**（`window.location.assign`），不用 `router.replace`：
  用客户端路由切 `/zh` ↔ `/en` 时会带着上一语言的 RSC 负载与客户端路由缓存，
  表现为「点了语言按钮一直转、要手动刷新才生效」。整页跳转代价只是一次导航，但状态干净。
  `RouteProgress` 另有 12 秒兜底：万一某次导航没产生 `pathname` 变化，进度条也会自己收尾，
  不会永远停在加载态。
- 验证环境：`export NODE_OPTIONS=""` 绕开沙箱的 safe-delete 垫片；本机无 Docker / nginx / ffmpeg。
- **端到端测试脚本在 `.verify/`**（不入库）：`api-smoke` / `comment-smoke` / `upload-smoke` /
  `console-scan` / `find-404` / `check-overflow` / `probe-styles` / `fix-verify`。
  跑 `upload-smoke` 必须单独把 `MEDIA_DIR` 指到临时目录，否则会往真实 uploads 里写文件。

## 十一、构建期环境变量（Docker）

前台页面在构建期预渲染会调 Prisma，所以 builder 阶段必须有 `DATABASE_URL`
（用一次性空库跑 `prisma migrate deploy` 即可）；而 `NEXT_PUBLIC_*` **会被内联进产物**，
`sitemap.xml` / `robots.txt` 依赖 `NEXT_PUBLIC_SITE_URL`，必须用 compose 的 `build.args` 在构建期传入。

构建期只有空库 → 页面先按空内容生成；`(site)/[locale]/layout.tsx` 与 `src/app/sitemap.ts`
都设了 `revalidate = 60`（**布局里的 route segment config 会传播到其下所有页面**），
容器启动写入种子后 60 秒内自动重新生成。新增前台页面时不要再单独写 `revalidate`，跟随布局即可。

**「配置了 Dockerfile」不等于「构建过」**：新增构建期依赖时必须在服务器或 CI 真跑一次。

## 十二、2026-10-21 全站体检与优化

这一轮按 **Ubuntu 24.04 / 4 核 4G / 1Mbps** 的部署目标做体检，改代码前先看这几条。

### 首屏减重（1Mbps 下收益最大）

- **字体分层**：正文/UI 用系统中文无衬线栈，站酷快乐体只留给 `--font-display`（见「一、UI 风格」）。
- **背景按视口取图**：内容区背景手机 640 / 桌面 1280；首页封面统一 1280（含 preload）；文章页背景改走 `/img/1280/`，不再直出上传原图。
- **小图走小档**：`/img` 宽度新增 128 / 256（Logo、开屏徽章、小图标不再拉 2560 原图）。
- **本地视频 `preload="none"`**：Chrome 对 `preload="metadata"` 会发 `Range: bytes=0-`，Nginx 会把整段 MP4 发回来（见「十」里 `<audio>` 的同类实测）。

### 服务端开销

- `getSiteVersion()` 改为 `unstable_cache` 缓存 60 秒，后台写操作通过 `revalidateTag("site-version")` 主动失效；`ConfigSync` 轮询降到 60 秒且页面不可见时不轮询。**之前是每个前台标签页每 10 秒读 14 张表（含全部文章正文）做 SHA1。**
- `getProfile` / `getPlaylist` 用 `react` 的 `cache()` 按请求去重（与 `getSiteInfo` 一致）。
- 分页 total 改用 count 查询，不再为拿 total 把全量 feed 查两遍；`total` 由页面传给视图组件。
- 浏览量 +1 显式回写原 `updatedAt`，不再污染 sitemap 的 `lastModified` 和文章「更新于」。
- 新增迁移 `20261021085758_add_perf_indexes`：`Comment(ipHash, createdAt)`（评论限频查询）、`Post(published, views)`（热门文章排序）。

### 安全与健壮性

- Nginx `X-Forwarded-For` 改为 `$remote_addr` **覆盖**；应用优先取 `X-Real-IP`，并用 `node:net` 校验 IP 合法性。之前取 XFF 第一段可被客户端伪造，登录/评论限频全失效。
- `/api/` 统一 1MB 请求体上限（分片上传 location 单独放宽到 200m/2100m/16m）；chunk 与 JSON 路由按 `Content-Length` 预检，超限直接 413。
- 备份 ZIP 导入：中央目录 ≤16MB、条目 ≤20000、`inflateRawSync` 带 `maxOutputLength`、流式解压超 `entry.size` 立即中止并清理半截文件。
- 备份导入的 `uploadId` 先校验再拼路径；媒体/软件条目按扩展名白名单落盘，跳过的写进 `warnings`。
- SVG 直出加 `Content-Security-Policy: sandbox` + `nosniff`（开发路由与 Nginx `/media/` 都加了），防存储型 XSS。
- Markdown 渲染后清洗 `a[href]` / `img[src]` 协议：只放行 http/https/mailto/tel/相对路径/锚点，img 额外允许 `data:image/`。
- 评论限频改为「进程内原子占位 + DB 复核」，并发不再能突破；浏览量服务端按 IP+slug 24h 去重。
- Prisma 错误映射：P2002→409、P2003→400、P2025→404（不再一律 500）。
- 生产环境 `JWT_SECRET` / `IP_HASH_SALT` 为占位值或过短时**直接报错**（fail-closed），部署时用 `openssl rand` 生成。
- 后台上传：所有 fetch 有超时、网络错误/5xx 自动重试 2 次，`uploading` 状态在 `finally` 复位；上传中禁用保存；补了 `(shell)/error.tsx`、401 之外的错误中文兜底。

### 已知限制（本轮未做，后续排期）

- **JWT 无服务端吊销**：退出登录只清 cookie，被窃 token 在有效期内仍可用；需要会话版本号/黑名单。
- 备份导出/导入仍把整库内容读进内存，4G 内存 + 大库有 OOM 风险。
- `/_next/static`、`/img` 仍回源 Node（Nginx 未开 `proxy_cache`）。
- 运行时镜像里多一份约 150MB 的 Prisma CLI（Dockerfile 二次 `npm install --no-save`，不走 lockfile）。
- `.imgcache` 无自动清理；`scripts/backup.sh` 是在线 tar，不能当可靠备份（部署手册里用停机冷备份）。
- 后台列表行仍用 index 作 key（上传中移动/删除行可能错位），目前靠「上传中禁用保存」缓解。
- 详情页仍跟随布局的 `revalidate=60` 整页重算：Next 的规则是**路由树里最小的 revalidate 生效**，page 里设 `false` 会被布局的 60 压过。要优化得把布局级 revalidate 拆到各列表页（改动面大，暂缓）。

## 十三、2026-10-21 二轮：排版、英文溢出与顶栏

这轮是纯前端视觉/排版调整（无数据库、无依赖变化）。

### 副标题：单行 + 循环打字机

- `typewriter.tsx` 重写为循环打字机：逐字打出 → 停留 2.6s → 逐字删除 → 650ms 后重来；`prefers-reduced-motion` 下直接显示整句、不循环。
- 副标题**不再换行**（`whitespace-nowrap`）。字号不是写死的：`hero-intro.tsx` 按字符宽度估算（中文 1em、英文 0.56em、空格 0.32em）反推 `calc((100vw - 2.75rem) / 估算宽度)`，再 clamp 到 `0.9rem ~ 1.6rem`，360~1440 宽下都能单行完整显示。
- 光标用 0.09em 细竖条而不是 `|` 字符，删除到空串时布局不塌。

### 顶栏：英文不再被裁

- 根因：顶栏内层是 `max-w-6xl`（1224px）**固定宽**，视口再宽导航可用空间也不增加；而 2xl 档曾把导航字号/内边距放大、并显示「Sign in / 登录」文字，1536px 起英文 12 项比可用宽度多约 70–90px，最后两项被裁。
- 修复：导航统一 `0.875rem`、`px-1.5`（删掉 2xl 放大）；`nav` 改 `flex-1 min-w-0 overflow-x-auto`；后台入口**始终只显示图标**（`aria-label` / `title` 保留，文字入口在移动端抽屉里）；站名 `max-w` 截断并带 `title`；1280px 起导航内边距统一收 1px。
- 回归脚本：`.verify/ui-verify.mjs`（不入库）用无头 Edge + DevTools 协议测 `document.scrollWidth`、`nav.scrollWidth > clientWidth`、副标题是否单行、移动端抽屉，并模拟长站名；另有 1440/390 中英文与深色全页截图。

公告板标题行、侧栏、分页、卡片元信息/标题、标签胶囊、评论/留言墙、页脚、弹窗/表格统一补 `min-w-0` / `flex-wrap` / `truncate` / `break-words`；首页侧栏「Announcements + View more (6)」实测溢出（305 > 262）已消除，英文按钮文案缩短为 `More (6)`。

### 视觉打磨

- `--radius` 0.375rem → 0.5rem；亮/暗两套 `--surface-shadow` 更柔和；`.surface` 圆角/阴影统一。
- `.page-heading h1` 统一移动 1.5rem / ≥640px 1.875rem，标题与内容间距统一 1.25 / 1.75rem；`.section-title` 行高 1.4。
- 导航选中态改为 2px 品牌色短下划线（hover 40%→100% 展开，无底色块）；标签/贴纸/书签 hover 位移收敛、补 `focus-visible` 焦点圈。
- 页脚：`flex-wrap` + 站名窄屏 42vw 截断、主题按钮移动端 44px、备案图标与文字对齐；移动端底部避让 `calc(6.5rem + env(safe-area-inset-bottom))`。

### 顺手修的 bug

- **ImageSkeleton 骨架常驻**：图片在 React 挂载前就从缓存 decode 完成时 `onLoad` 不再触发，封面骨架永远转、图片 `opacity-0`（小 SVG 封面实测必现）。现在挂载后主动检查 `img.complete` / `naturalWidth` 补状态。
- **手机端评论表情弹层被裁**：弹层原来用 `absolute` 相对按钮定位（`align="right"`），375/390 下实际 `left=-150`，近一半表情在视口外点不到。改为 `portal + fixed`：按按钮位置计算、水平夹在视口安全边距内，上方放不下自动翻到下方并限制高度内部滚动；点外部/按 Esc 关闭时同时判断按钮与弹层。
- **自定义光标尖头与猫身重叠**：`scripts/make-cursor.mjs` 用 36×36 画布，尖头放大到约 10px（太小不像指针）、猫身 24px 向右下错开并留约 1px 空隙，热点保持 `2 2`（点击位置不变）。浏览器对自定义光标有尺寸上限（Chromium 128px），不要大幅放大画布。

### 双语副标题（2026-10-21）

首页封面副标题支持中英两份，规则与文章 `titleEn` / `contentEn` 一致：

- 新增 Setting 键 `site.subtitleEn`（后台「站点设置 → 站点信息 → 英文副标题」）；
- `/en` 优先用 `subtitleEn`，**留空回退中文 `site.subtitle`**；两者都空再回退 `site.description` / 个人简介；
- `/zh` 始终用中文副标题；
- 写入仍走 `PUT /api/admin/settings/site`（限 120 字符），保存后由 `revalidateSiteSettings()` 刷前台、`revalidateTag("site-version")` 让打开的标签页自己刷新；
- 注意：`site.description` 仍是单语（主要给 SEO description 用），本次只做了副标题双语。
