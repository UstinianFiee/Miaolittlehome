# 旧站更新（Git 版，保留数据）

> **之前用压缩包 + Docker Compose 部署？请改看 [压缩包更新手册](./压缩包更新手册.md)，不要执行下面的 Git 命令。**

更新：2026-10-15。适用于原目录中的 Linux / Git / Docker Compose v2 部署。**不重新部署、不重新初始化。** 原文章、评论、图片、软件和设置继续使用原数据库及原数据目录；自动迁移前仍须备份。

## 1. 保留配置，先备份

进入服务器上的**原项目目录**，保留原 `.env.production`、`DATA_DIR`、Nginx 配置和证书；只确认 `RUN_SEED=false`，不要从模板覆盖配置。

**先按 [完整操作第 1、2 步](./DEPLOY.md#safe-update) 核对旧容器实际挂载、停机并完整冷备份。** 备份包含数据库（含存在的 WAL）、媒体、软件、配置、证书和旧代码/镜像，放在数据目录之外。原 `scripts/backup.sh` 不能代替此冷备份。

完成后保持**同一个 Bash 会话**继续，下面的 `check_config` 函数由上述第 1 步定义。若不采用默认编排、使用命名卷或找不到原数据，请停止，不直接套用。

## 2. 拉取并复核

```bash
git pull --ff-only
check_config
```

对照备份确认原配置、Nginx 定制、证书和数据挂载未被意外改变。**有冲突或报错就停止**，不要 reset、删项目重来或换成空数据目录。

## 3. 启动并检查

```bash
docker compose --env-file .env.production up -d --build --wait app
docker compose --env-file .env.production up -d --no-deps --force-recreate nginx
docker compose --env-file .env.production exec nginx nginx -t
docker compose --env-file .env.production ps
docker compose --env-file .env.production logs --tail=80 app nginx
```

确认 app 健康、迁移无报错，网站和 `/admin` 可用，**旧文章、评论、图片、软件、设置都在**，再恢复公众访问和定时任务。无需手动运行数据库迁移，也不运行 seed；`--wait` 失败不继续启动 Nginx。

**三条底线：**不删除原数据目录；不执行 `docker compose down -v`；不把备份解压覆盖活数据库。失败就停服务并保存现场，按 [回滚说明](./DEPLOY.md#rollback) 恢复同一检查点的代码、数据和配置，不能只回退代码。

本次发布包含青碧主题、小型透明星环、随机播放和说说尖角修复，**没有新增数据库迁移或依赖变更**。文档已核对仓库实现，未代替你执行服务器部署或恢复演练。
