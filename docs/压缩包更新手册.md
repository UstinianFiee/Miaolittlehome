# 压缩包更新（保留原文章和上传文件）

更新：2026-10-15。适用于原来用 **ZIP 压缩包 + Docker Compose** 部署的站点，**不用 Git，不执行 git pull，不重新初始化**。需要 Linux 和支持 `--wait` 的 Docker Compose v2。

## 1. 新包单独解压

把新版源码包解压到一个**新的临时目录**，找到里面有 `Dockerfile`、`docker-compose.yml` 的项目根目录。**不要直接解压覆盖旧项目，也不要在新目录启动容器。** 本次应用版本为 `7706a58`（青碧主题、星环和随机播放）。

## 2. 在旧目录停机、完整备份

进入服务器上的**原项目目录**，保留原 `.env.production`，将其中 `RUN_SEED` 确认为 `false`；不要用模板覆盖。按 [无 Git 备份步骤](./DEPLOY.md#archive-update) 核对旧容器的真实数据挂载，停机并完整备份**数据 + 旧项目 + 配置/证书 + 旧镜像**。备份放在项目与数据目录之外。

仅从后台导出内容不等于完整部署备份；原 `scripts/backup.sh` 也不能代替这里的停机冷备份。备份失败就停止更新。

## 3. 只换程序，保留生产文件

备份成功后仍使用**原项目目录和原 Compose 项目名**。从新包更新下列程序内容：

- 目录：`src/`、`messages/`、`public/`、`prisma/`、`scripts/`、`docs/`。旧版本目录先移到私有备份区，再放入完整新版目录，**不要只合并文件而留下过期代码**。若这些目录有真实数据库、上传文件或自定义资源，先停止并单独核对，不能按纯程序目录处理。
- 文件：`Dockerfile`、`package.json`、`package-lock.json`、`next.config.ts`、`tsconfig.json`、`postcss.config.mjs`、`components.json`、`.dockerignore`、`.nvmrc`、`README.md`、`deploy/entrypoint.sh`。复制时保留脚本 LF 换行。
- 仓库 `data/` 中的离线 IP 库如有更新，只逐个更新对应库文件；**不能整目录覆盖实际生产 DATA_DIR**。

**原样保留：**原 `.env` / `.env.production`、真实数据目录（含数据库、媒体、软件、备份）、`uploads/`、`software/`、Nginx 配置和证书，以及其他生产定制。不要复制示例媒体或重新运行 seed。

**`docker-compose.yml` 不整份覆盖：**与新版对照合并必要差异，保留原端口、项目名、挂载和定制。app 容器内 `DATA_DIR` 应固定为 `/data`；宿主挂载仍指向原目录。构建时保留 `NEXT_PUBLIC_SITE_URL` 参数。有额外 Compose 文件、命名卷、外部证书或不明挂载时，先单独核对，不直接套用。

## 4. 原目录重建并检查

使用原来的 Compose 参数；标准部署在原目录、同一个 Bash 会话执行（失败立即停止）：

```bash
set -euo pipefail
check_archive_config
docker compose --env-file .env.production up -d --build --wait app
docker compose --env-file .env.production up -d --no-deps --force-recreate nginx
docker compose --env-file .env.production exec nginx nginx -t
docker compose --env-file .env.production ps
docker compose --env-file .env.production logs --tail=80 app nginx
```

`check_archive_config` 在上述 [无 Git 备份步骤](./DEPLOY.md#archive-update) 中定义：用于再次核对新配置没有换数据目录，并确认初始化关闭。不要省略；换了终端须重新核对旧挂载记录。

检查网站、`/admin`、旧文章、评论、图片、软件和设置；确认正常再恢复公网访问、自动部署和定时任务。迁移由容器启动时自动执行，不需要手工迁移。

**不要做：**删除旧数据、执行 `down -v`、启动新目录产生另一套空库、将备份直接覆盖活库。失败时停服务、保存现场，按 [配套回滚](./DEPLOY.md#rollback) 恢复同一检查点的代码/镜像、数据和配置；仅换回旧代码不够。

本次应用改动未新增数据库迁移或依赖，但从更早版本更新仍可能执行待应用迁移，因此不能省略备份。本文未代替你操作服务器或完成恢复演练。
