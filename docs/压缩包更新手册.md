# 压缩包更新（保留原文章和上传文件）

更新：2026-10-21。适用于原来用 **ZIP 压缩包 + Docker Compose** 部署的站点，**不用 Git，不执行 git pull，不重新初始化**。需要 Linux 和支持 `--wait` 的 Docker Compose v2。

|---|---|

| 内容 | 完整源码（`src/` `messages/` `public/` `prisma/` `scripts/` `docs/` `deploy/` 与根配置文件）；**不含** `.env*`、数据库、`node_modules`、运行时上传与软件包 |

### 升级前必须确认

1. `.env.production` 里 `JWT_SECRET`、`IP_HASH_SALT` 必须是强随机值（`openssl rand -base64 48` / `openssl rand -base64 32`）。新版会拒绝模板占位值：漏改会导致**后台登录、评论提交不可用**（启动日志会给出醒目提示）。
2. `RUN_SEED=false`，且不要用模板覆盖现有 `.env.production`。
3. 完成第 2 步的停机冷备份；备份失败就停止更新。

### Nginx 差异（有自定义配置时按这几处合并）

- `proxy_set_header X-Forwarded-For $remote_addr;`（旧版是 `$proxy_add_x_forwarded_for`，可被客户端伪造，会让登录/评论限频失效）
- 新增 `/api/` 请求体上限 `1m`；媒体、备份、软件包上传的 location 单独放宽（旧站的这些 location 保持原值即可，只补 `/api/` 与 `/api/admin/media/` 两段）
- `/media/` 增加 `Content-Security-Policy: sandbox`（防用户上传的 SVG 在站内执行脚本）

## 1. 新包单独解压

把 `miaolittlehome-20261021-update.zip` 解压到一个**新的临时目录**，确认里面有 `Dockerfile`、`docker-compose.yml`（压缩包内顶层目录为 `miaolittlehome/`）。**不要直接解压覆盖旧项目，也不要在新目录启动容器。**

## 2. 在旧目录停机、完整备份

进入服务器上的**原项目目录**，保留原 `.env.production`，确认 `RUN_SEED=false`。按 [无 Git 备份步骤](./DEPLOY.md#archive-update) 核对旧容器真实数据挂载，停机并完整备份**数据 + 旧项目 + 配置/证书 + 旧镜像**，放在项目与数据目录之外。备份失败就停止更新。

仅从后台导出内容不等于完整部署备份；`scripts/backup.sh` 也不能代替停机冷备份。

## 3. 只换程序，保留生产文件

备份成功后仍使用**原项目目录和原 Compose 项目名**，从新包更新下列内容：

- **目录**：`src/`、`messages/`、`public/`、`prisma/`、`scripts/`、`docs/`。旧目录先移到私有备份区，再放入完整新版目录，**不要只合并文件而留下过期代码**。`prisma/` 里包含本次新增的迁移，必须整目录替换，只新增不修改历史迁移。
- **文件**：`Dockerfile`、`package.json`、`package-lock.json`、`next.config.ts`、`tsconfig.json`、`postcss.config.mjs`、`components.json`、`.dockerignore`、`.nvmrc`、`README.md`、`deploy/entrypoint.sh`（复制时保持 LF 换行）。
- **`deploy/nginx/nginx.conf`**：按上面「Nginx 差异」合并，**不要覆盖**原域名 `map`、证书路径和自定义规则。
- 仓库 `data/` 里的离线 IP 库如果有更新，只逐个替换对应库文件；**不能整目录覆盖生产 `DATA_DIR`**。

**原样保留：** 原 `.env` / `.env.production`、真实数据目录（数据库、媒体、软件、备份）、`uploads/`、`software/`、Nginx 自定义配置和证书。不要复制示例媒体，不要重新运行 seed。

**`docker-compose.yml` 不整份覆盖**：与新版对照合并必要差异，保留原端口、项目名、挂载和定制。app 容器内 `DATA_DIR` 固定为 `/data`，宿主挂载仍指向原目录；保留构建期的 `NEXT_PUBLIC_SITE_URL`。

## 4. 原目录重建并检查

使用原来的 Compose 参数，在同一个 Bash 会话执行（失败立即停止）：

```bash
set -euo pipefail
check_archive_config
docker compose --env-file .env.production up -d --build --wait app
docker compose --env-file .env.production up -d --no-deps --force-recreate nginx
docker compose --env-file .env.production exec nginx nginx -t
docker compose --env-file .env.production ps
docker compose --env-file .env.production logs --tail=80 app nginx
```

`check_archive_config` 在 [无 Git 备份步骤](./DEPLOY.md#archive-update) 中定义：再次核对新配置没有换数据目录、初始化已关闭。

检查项：网站、`/admin` 登录、旧文章/评论/图片/软件和设置都在；首页中文副标题正常，切到 `/en` 若后台填了「英文副标题」会显示英文、留空则回退中文；提交一条评论确认限频生效。

> 数据库迁移由容器启动时自动执行，**不要手动跑 migrate**，也不要为了让内容出现而重新 seed。

## 5. 回滚

停服务、保存现场，按 [配套回滚](./DEPLOY.md#rollback) 恢复同一检查点的**代码/镜像 + 数据 + 配置**；只换回旧代码不够。

**不要做：** 删除旧数据、执行 `down -v`、启动新目录产生另一套空库、把备份直接覆盖活库。

本次更新新增 1 个数据库迁移、无新增依赖；从更早版本更新仍可能执行待应用迁移，因此不能省略冷备份。本文未代替你操作服务器或完成恢复演练。
